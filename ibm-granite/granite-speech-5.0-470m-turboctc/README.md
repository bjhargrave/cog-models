# ibm-granite/granite-speech-5.0-470m-turboctc

A [Replicate](https://replicate.com) [Cog](https://cog.run) container that serves the **IBM Granite Speech 5.0 470M TurboCTC** automatic speech recognition model using [Hugging Face Transformers](https://huggingface.co/docs/transformers) as the inference backend. It is published as [`r8.im/ibm-granite/granite-speech-5.0-470m-turboctc`](https://replicate.com/ibm-granite/granite-speech-5.0-470m-turboctc).

## How it works

```
┌────────────────────────────────────────────┐
│  Replicate platform                        │
│                                            │
│  HTTP request ──► Cog runtime              │
│                      │                     │
│                      ▼                     │
│               Runner (run.py)              │
│                      │                     │
│                      ▼                     │
│            ProducerConsumer queue          │
│          (AudioWorker, max=10 slots)       │
│                      │                     │
│                      ▼                     │
│         Runner.transcribe() [async]        │
│                      │                     │
│                      ▼                     │
│      AutoModelForCTC + AutoProcessor       │
│                      │                     │
│                      ▼                     │
│         Model weights (/src/weights)       │
└────────────────────────────────────────────┘
```

The Cog `Runner` class in [`run.py`](run.py) is the entry point. On startup it:

1. Reads [`runner_config.json`](runner_config.json) to configure the model path and `AutoModelForCTC` kwargs.
2. Loads the processor (`AutoProcessor`) and the CTC model (`AutoModelForCTC`) from the weights directory.
3. Starts a `ProducerConsumer` background worker (`AudioWorker`) with a queue depth of 10.
4. Runs a single warmup inference using [`multilingual_sample.wav`](multilingual_sample.wav) so the GPU is hot before the first real request.

Each prediction call (`run()`) accepts a list of audio inputs, enqueues them as a single `AudioRequest`, waits for the `AudioWorker` to return an `AudioResponse`, and yields one transcript string per audio file.

## Key files

| File | Purpose |
|---|---|
| [`cog.yaml`](cog.yaml) | Cog build and runtime configuration — CUDA version, Python version. |
| [`run.py`](run.py) | The Cog `Runner` class: `setup()` loads the model; `run()` handles each prediction. |
| [`runner_config.json`](runner_config.json) | Runtime tuning — served model name and `AutoModelForCTC` kwargs (e.g. `trust_remote_code`, `device_map`). |
| [`pyproject.toml`](pyproject.toml) | Python project definition; pins Transformers, PyTorch, and the CUDA 12.9 torch backend. |
| [`requirements.txt`](requirements.txt) | Fully-pinned lockfile generated by `uv pip compile`; used during the Docker build. |
| [`multilingual_sample.wav`](multilingual_sample.wav) | Warmup audio clip played during `setup()` to pre-heat the model. |
| [`tests/`](tests/) | JSON input fixtures for manual end-to-end testing via `python run.py tests/*.json`. |
| [`weights/`](weights/) | Downloaded model weights (populated by `hf download`; not committed). |

## Inputs

The `run()` method accepts the following inputs.

| Input | Type | Default | Description |
|---|---|---|---|
| `audio` | `list[Path] \| None` | `null` | One or more audio files to transcribe. Accepts file paths or `data:` URIs (e.g. `data:audio/wav;base64,…`). WAV, OGG, and any format supported by `soundfile` are accepted. Audio is automatically resampled to the model's native sampling rate if needed. |

### Output

The prediction yields one `str` transcript per supplied audio file, in the same order as the input list. Transcripts are plain text with special tokens removed.

## Runtime configuration (`runner_config.json`)

[`runner_config.json`](runner_config.json) is loaded at startup by `Runner.load_config()`. It maps to the `RunnerConfig` Pydantic model.

```json
{
    "served_model_name": "ibm-granite/granite-speech-5.0-470m-turboctc",
    "model_kwargs": {
        "trust_remote_code": true,
        "device_map": "auto"
    }
}
```

The `model_kwargs` object is forwarded verbatim to `AutoModelForCTC.from_pretrained()`. Any keyword argument accepted by that call can be added here without changing `run.py`.

## Build

The image is built with [Cog](https://cog.run). The Cog CLI version must match the `sdk_version` declared in [`cog.yaml`](cog.yaml) — currently **`0.21.0`**.

```bash
# Install Cog 0.21.0 (must match sdk_version in cog.yaml)
sudo curl -o /usr/local/bin/cog -L https://github.com/replicate/cog/releases/download/v0.21.0/cog_$(uname -s)_$(uname -m)
sudo chmod +x /usr/local/bin/cog

# Confirm the installed version
cog --version

# Build the image
cog build --use-cog-base-image --separate-weights
```

Cog reads [`cog.yaml`](cog.yaml) and produces a Docker image. The build step runs:

```
uv pip install --requirements requirements.txt --torch-backend=cu129
```

This installs the fully-pinned dependency set from [`requirements.txt`](requirements.txt) into the image. The `--torch-backend=cu129` flag selects the CUDA 12.9 PyTorch wheel.

### Updating dependencies

[`requirements.txt`](requirements.txt) is generated by `uv`. To regenerate it after editing [`pyproject.toml`](pyproject.toml):

```bash
uv pip compile pyproject.toml --output-file requirements.txt
```

## Model weights

Weights are downloaded into the `weights` folder:

```bash
hf download --local-dir weights ibm-granite/granite-speech-5.0-470m-turboctc
```

Cog bakes them into the image at `/src/weights`. The `Runner` resolves the weights path at startup and passes it to `AutoModelForCTC.from_pretrained()`.

## Local testing

The `__main__` block at the bottom of [`run.py`](run.py) lets you run inference directly from the command line, loading the model from the local `weights` folder.

```bash
# Download the model to the local weights folder first
hf download --local-dir weights ibm-granite/granite-speech-5.0-470m-turboctc

# Run against one or more JSON test fixtures
python run.py tests/audio_url.json
```

Each fixture file is a plain JSON object whose keys map to `run()` input parameters. The test files in [`tests/`](tests/) cover the main usage patterns:

| Fixture | Scenario |
| --- | --- |
| `audio_url.json` | Transcription from inline `data:` URI audio inputs (WAV and OGG) |

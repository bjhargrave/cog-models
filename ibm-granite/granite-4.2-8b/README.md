# ibm-granite/granite-4.2-8b

A [Replicate](https://replicate.com) [Cog](https://cog.run) container that serves the **IBM Granite 4.2 8B** language model using [vLLM](https://docs.vllm.ai) as the inference backend. It is published as [`r8.im/ibm-granite/granite-4.2-8b`](https://replicate.com/ibm-granite/granite-4.2-8b).

## How it works

```
┌─────────────────────────────────────────────────┐
│  Replicate platform                             │
│                                                 │
│  HTTP request ──► Cog runtime                   │
│                      │                          │
│                      ▼                          │
│               Runner (run.py)                   │
│                      │                          │
│           ┌──────────┴──────────┐               │
│           ▼                     ▼               │
│  Chat Completion API     Completion API         │
│  (OpenAIServingChat)  (OpenAIServingCompletion) │
│           └──────────┬──────────┘               │
│                      ▼                          │
│           vLLM AsyncLLM engine                  │
│                      │                          │
│                      ▼                          │
│           Model weights (/src/weights)          │
└─────────────────────────────────────────────────┘
```

The Cog `Runner` class in [`run.py`](run.py) is the entry point. On startup it:

1. Reads [`runner_config.json`](runner_config.json) to configure vLLM engine args and serving options.
2. Initialises a vLLM `AsyncLLM` engine pointing at the model weights.
3. Wires up `OpenAIServingChat` and `OpenAIServingCompletion` — the same serving layer used by the vLLM OpenAI-compatible HTTP server.
4. Runs a single warmup inference so the GPU is hot before the first real request.

Each prediction call (`run()`) routes to either the **Chat Completion** path (when `messages` is supplied) or the **Completion** path (when only `prompt` is supplied), and streams tokens back to the caller as they are generated.

## Key files

| File | Purpose |
|---|---|
| [`cog.yaml`](cog.yaml) | Cog build and runtime configuration — CUDA version, Python version, model weights source, concurrency limit. |
| [`run.py`](run.py) | The Cog `Runner` class: `setup()` initialises vLLM; `run()` handles each prediction. |
| [`runner_config.json`](runner_config.json) | Runtime tuning — engine args, tool-call parser, reasoning parser, logging flags. |
| [`pyproject.toml`](pyproject.toml) | Python project definition; pins vLLM and the CUDA 12.9 torch backend. |
| [`requirements.txt`](requirements.txt) | Fully-pinned lockfile generated by `uv pip compile`; used during the Docker build. |
| [`tests/`](tests/) | JSON input fixtures for manual end-to-end testing via `python run.py tests/*.json`. |
| [`weights/`](weights/) | Downloaded model weights (populated by `cog weights import` or `cog run`; not committed). |

## Inputs

The `run()` method accepts the following inputs.

### Content inputs (one is required)

| Input | Type | Description |
|---|---|---|
| `prompt` | `str \| None` | Plain-text user prompt. Converted to a `user` message before being sent to the Chat Completion API. If the prompt already begins with the model's start token it is passed directly to the Completion API instead. |
| `messages` | `list[object] \| None` | Full OpenAI-style message array (e.g. `[{"role": "user", "content": "…"}]`). Takes priority over `prompt`/`system_prompt` when both are supplied. |

### Prompt shaping

| Input | Type | Default | Description |
|---|---|---|---|
| `system_prompt` | `str \| None` | `null` | Prepended as a `system` message when using the `prompt` path. |
| `documents` | `list[object] \| None` | `null` | Document context objects passed to the chat template (RAG use-cases). |
| `chat_template` | `str \| None` | `null` | Override the model's built-in chat template. |
| `add_generation_prompt` | `bool` | `true` | Append the generation-prompt token sequence to the formatted input. |
| `chat_template_kwargs` | `dict \| None` | `null` | Extra kwargs forwarded to the Jinja chat template, e.g. `{"enable_thinking": true}`. |

### Tool use

| Input | Type | Default | Description |
|---|---|---|---|
| `tools` | `list[object] \| None` | `null` | OpenAI tool definitions. |
| `tool_choice` | `str \| None` | `null` | `"none"`, `"auto"`, `"required"`, or a JSON string for a specific function, e.g. `{"type":"function","function":{"name":"my_fn"}}`. |

### Structured output

| Input | Type | Default | Description |
|---|---|---|---|
| `response_format` | `object \| None` | `null` | OpenAI `response_format` object, e.g. `{"type": "json_schema", "json_schema": {…}}`. |

### Sampling parameters

| Input | Type | Default | Description |
|---|---|---|---|
| `max_completion_tokens` | `int \| None` | `null` | Maximum tokens to generate (replaces the deprecated `max_tokens`). |
| `min_tokens` | `int` | `0` | Minimum tokens before the model may stop. |
| `temperature` | `float \| None` | `null` | Sampling temperature. `0.0` gives greedy decoding. |
| `top_p` | `float \| None` | `null` | Nucleus sampling threshold. |
| `top_k` | `int \| None` | `null` | Top-K sampling. |
| `presence_penalty` | `float \| None` | `null` | Penalise tokens that have appeared at all. |
| `frequency_penalty` | `float \| None` | `null` | Penalise tokens proportional to how often they have appeared. |
| `repetition_penalty` | `float \| None` | `null` | Multiplicative repetition penalty. |
| `stop` | `list[str] \| None` | `null` | Stop sequences, e.g. `["<end>", "<stop>"]`. |
| `seed` | `int \| None` | `null` | Fixed RNG seed for reproducible outputs. |

### Streaming

| Input | Type | Default | Description |
|---|---|---|---|
| `stream` | `bool \| None` | `null` | When `true`, returns SSE-formatted `data:` chunks instead of a single response. |

### Output

The prediction always yields a stream of `str` tokens via `AsyncConcatenateIterator[str]`. Replicate concatenates them into the final output. When `messages` is passed (Chat Completion path) **and** `stream` is `false`, the single yielded string is a complete JSON-serialised `ChatCompletionResponse` object. Otherwise it is plain text.

## Runtime configuration (`runner_config.json`)

[`runner_config.json`](runner_config.json) is loaded at startup by `Runner.load_config()`. It maps to the `RunnerConfig` Pydantic model.

```json
{
    "chat_template_content_format": "string",
    "enable_log_requests": true,
    "enable_force_include_usage": true,
    "enable_auto_tool_choice": true,
    "tool_call_parser": "qwen3_coder",
    "reasoning_parser": "nemotron_v3",
    "log_error_stack": true,
    "engine_args": {
        "served_model_name": "ibm-granite/granite-4.2-8b",
        "gpu_memory_utilization": 0.95,
        "trust_remote_code": false,
        "override_generation_config": {
            "temperature": 0.0
        }
    }
}
```

The `engine_args` object is forwarded verbatim to vLLM's `AsyncEngineArgs`. Any field supported by `AsyncEngineArgs` can be added here without changing `run.py`. The `tensor_parallel_size` is set automatically at runtime from the number of available CUDA devices.

## Build

The image is built with [Cog](https://cog.run). The Cog CLI version must match the `sdk_version` declared in [`cog.yaml`](cog.yaml) — currently **`0.21.0`**.

```bash
# Install Cog 0.21.0 (must match sdk_version in cog.yaml)
sudo curl -o /usr/local/bin/cog -L https://github.com/replicate/cog/releases/download/v0.21.0/cog_$(uname -s)_$(uname -m)
sudo chmod +x /usr/local/bin/cog

# Confirm the installed version
cog --version

# Build the image
cog build
```

Cog reads [`cog.yaml`](cog.yaml) and produces a Docker image. The build step runs:

```
uv pip install --requirements requirements.txt --torch-backend=cu129
```

This installs the fully-pinned dependency set from [`requirements.txt`](requirements.txt) into the image. The `--torch-backend=cu129` flag selects the CUDA 12.9 PyTorch wheel.

### Updating dependencies

[`requirements.txt`](requirements.txt) is generated by `uv`. To regenerate it after editing [`pyproject.toml`](pyproject.toml):

```bash
uv pip compile pyproject.toml --output-file requirements.txt
```

## Model weights

Weights are declared in [`cog.yaml`](cog.yaml):

```yaml
weights:
  - name: granite-4.2-8b
    source:
      uri: hf://ibm-granite/granite-4.2-8b
    target: /src/weights
```

Cog downloads them from Hugging Face and bakes them into the image at `/src/weights`. The `Runner` resolves the weights path at startup and passes it directly to the vLLM engine.

## Local testing

The `__main__` block at the bottom of [`run.py`](run.py) lets you run inference directly from the command line, loading the model from the local Hugging Face cache rather than from `/src/weights`.

```bash
# Download the model to the HF cache first
hf download ibm-granite/granite-4.2-8b

# Run against one or more JSON test fixtures
python run.py tests/prompt.json
python run.py tests/chat.json tests/chat_thinking.json
```

Each fixture file is a plain JSON object whose keys map to `run()` input parameters. The test files in [`tests/`](tests/) cover the main usage patterns:

| Fixture | Scenario |
|---|---|
| `prompt.json` | Plain text prompt |
| `prompt_stream.json` | Streamed plain text prompt |
| `prompt_formatted.json` | Pre-formatted prompt (passes start token directly to Completion API) |
| `prompt_documents.json` | RAG with document context |
| `prompt_tool_call.json` | Tool use via the Completion API |
| `prompt_thinking.json` | Extended thinking mode via Completion API |
| `prompt_response_format.json` | Structured JSON output via Completion API |
| `chat.json` | Chat Completion with sampling parameters |
| `chat_stream.json` | Streamed Chat Completion |
| `chat_content_array.json` | Multi-part content array messages |
| `chat_documents.json` | RAG with document context |
| `chat_tool_call.json` | Tool use with explicit function selection |
| `chat_tool_call_response.json` | Tool result fed back into the conversation |
| `chat_thinking.json` | Extended thinking mode |
| `chat_response_format.json` | Structured JSON output |

## Environment variables

| Variable | Default | Description |
|---|---|---|
| `RUNNER_LOG_LEVEL` | `DEBUG` | Python log level for the runner logger. |
| `VLLM_WORKER_MULTIPROC_METHOD` | `spawn` | Set before importing vLLM to control worker process creation (required for correctness). |

Any `VLLM_*` environment variable recognised by vLLM can also be set to tune engine behaviour.
